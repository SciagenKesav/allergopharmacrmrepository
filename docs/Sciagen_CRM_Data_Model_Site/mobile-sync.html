Mobile Sync and System Data Model

Entities and relationships for the iPad sync log, per-object sync configuration, geocoding and application configuration.

Scroll or zoom the diagram. In the PDF it is scaled to the page.

Entities/Objects Included

Geocoding Config, Sciagen App Config, Sync Object Config, Sync Tracking

How it works in our org

  • Sync Tracking records one row per record the iPad pushes, with its status (Pending, Synced, Failed, Deleted or Skipped), the error text and the Salesforce id; rows older than the retention window are purged.
  • Sync Object Config is custom metadata saying, per object family, whether it syncs, in which direction (Salesforce to iPad, iPad to Salesforce, or both), the sync window and who wins a conflict. App Config and Geocoding Config hold global settings.

Sync Object Config Sync_Object_Config__mdt 5 fields

Sync-direction gateway for the iPad app. One record per Salesforce object family the app can sync — controls whether it syncs at all, in which direction (Salesforce to iPad, iPad to Salesforce, or Bi-Directional), and which side wins if the same record changed on both sides. Editable here in Setup with no deployment — the app always reads current values from these records rather than assuming any policy in code.
